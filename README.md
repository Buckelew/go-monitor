# go-monitor

Watches online stores and posts to Discord when a product drops, restocks, or gets pulled.

I used to run a handful of separate monitor scripts for collectible drops, and this replaced them. It's one Go binary: the Discord bot, the monitors, and a small web dashboard all run in the same process, backed by Postgres.

## What it watches

| Site | How it checks |
| --- | --- |
| Shopify | pages through the store's `products.json` |
| Big Cartel | the store's `products.json` |
| Squarespace | `?format=json` on the shop page |
| LEGO | LEGO's product GraphQL API |
| Reddit | `/r/<sub>/new.json` for new posts |
| Target | tries an add-to-cart to see if an item is really in stock |

You paste a URL into the dashboard and it figures out which site it is. Each check gets compared to the last one, and changes turn into one of five events: `new_product`, `restock`, `delisted`, `password_up`, or `password_down` (Shopify stores put up a password page before a drop). The first run for a new task only records what's there, so you don't get flooded with alerts.

## How it runs

- Each site gets its own runner that loops over that site's tasks. How fast it ticks depends on how many proxies that site has: one tick per second per proxy, never faster than every 100ms, and every 3s with no proxies. A single task never runs more than once a second.
- Changes go into an in-process hub. The Discord side subscribes to it and sends an embed to every channel subscribed to that task. The API also streams events over a WebSocket.
- The dashboard is server-rendered Go templates. Log in with Discord, add tasks, manage proxies, and look through recent runs (status, response time, cache hits).
- Data lives in Postgres, with queries generated by [sqlc](https://sqlc.dev) and migrations run by `golang-migrate`.
- Pushing to `main` builds a Docker image, pushes it to GHCR, then SSHes into the server and restarts it with `docker compose`.

Target checks need a solver service for Target's bot protection. Set `SOLVER_BASE_URL` and `SOLVER_API_TOKEN`, or leave Target out.

## Layout

```
cmd/monitor           entry point
internal/monitor      scheduler, task types, one folder per site under platforms/
internal/hub          pub/sub between the monitors and everything else
internal/discord      bot, embeds, subscription fan-out
internal/web          dashboard (templates + static)
internal/api          JSON API, Discord OAuth, WebSocket
internal/database     sqlc output and queries
migrations            SQL migrations
```

## Running it locally

You need Go 1.25 and Postgres 18.

1. Copy the env file and fill it in. At minimum you need `DISCORD_TOKEN` and the Postgres values.

```bash
cp .env.example .env
```

2. Create the databases.

```bash
createdb go_monitor
createdb go_monitor_test
```

3. Install the migrate CLI, run migrations, and seed.

```bash
make bin-deps
make migrate-up
make seed
```

4. Start it.

```bash
make run
```

Tests hit a real Postgres database (`go_monitor_test`):

```bash
make test
```
